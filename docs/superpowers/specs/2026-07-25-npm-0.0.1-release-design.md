# npm 0.0.1 Release Design

## Summary

Release the first public `ants-move` package to the official npm registry as version `0.0.1` with the `latest` distribution tag. Publish the exact tarball that passes local package inspection and installation checks.

The release changes package metadata only. It does not change collector behavior, create a Git commit, push Git changes, create a Git tag, or publish any other version.

## Metadata

- Change `package.json` version from `0.1.0` to `0.0.1`.
- Keep the root package versions in `package-lock.json` synchronized at `0.0.1`.
- Extend the package scaffolding test to assert the release version.
- Keep the package name `ants-move`, the `ants` and `amv` binaries, and all other metadata unchanged.

## Release Flow

1. Add a metadata assertion for version `0.0.1` and verify that it fails against the current `0.1.0` package metadata.
2. Update `package.json` and `package-lock.json` to `0.0.1`, then verify the focused metadata test passes.
3. Confirm the npm registry is `https://registry.npmjs.org/`, the authenticated identity is `stephenyang`, and `ants-move@0.0.1` is not already published.
4. Run type checking, the full test suite, coverage, build, and the offline production dependency audit.
5. Create `ants-move-0.0.1.tgz` with `npm pack --json` and verify its file list, package version, executable mode, and Node shebang.
6. Install that exact tarball under a fresh temporary npm prefix and verify both `ants --help` and `amv --help`.
7. Publish that exact tarball with public access and the `latest` tag.
8. Query npm after publication and confirm that version `0.0.1` exists and `dist-tags.latest` equals `0.0.1`.

## Failure Handling

- Stop before publication if authentication, version availability, tests, coverage, build, audit, tarball inspection, or isolated installation fails.
- Do not automatically retry `npm publish`. A timeout can leave publication status uncertain, so query the registry before deciding what to do next.
- If npm requires an OTP or web confirmation, pause and request the required user action without exposing credentials.
- Treat the registry as the atomic authority for version uniqueness. The preflight availability check can race with another publisher, but npm must reject a duplicate immutable version.
- After a confirmed successful publication, do not attempt to overwrite or unpublish the release.

## Concurrency And Resource Review

The metadata change does not affect production request paths, collector fan-out, locks, caches, jobs, or persistent runtime state. The release process performs one bounded build, one tarball installation, and one publication attempt.

There is no local check-then-create guarantee for package version ownership. The npm registry resolves that race atomically by accepting at most one publication for `ants-move@0.0.1`. No background publish, retry queue, or multi-instance release worker is introduced.

## Verification And Handoff

Success requires all deterministic checks to pass, the installed tarball to expose both binaries, and npm registry reads to confirm the published version and `latest` tag. The generated tarball and temporary installation directory will be removed after verification.

The version and test changes remain uncommitted in the local `dev` branch. No Git commit, Git push, Git tag, GitHub release, or additional npm version is authorized by this release request.
