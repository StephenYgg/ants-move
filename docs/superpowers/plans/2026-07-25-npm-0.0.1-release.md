# npm 0.0.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the first public `ants-move` package as version `0.0.1` with the npm `latest` tag.

**Architecture:** Treat package version as tested metadata, then build and inspect one tarball and use that same immutable artifact for isolated installation and npm publication. npm is the atomic authority for package-version uniqueness; the workflow performs one publication attempt and verifies registry state afterward.

**Tech Stack:** npm, TypeScript, Vitest, tsup, Node.js 22

**Git Constraint:** Leave all release changes uncommitted. Do not create a Git commit, tag, push, or GitHub release.

---

### Task 1: Lock The Release Version With A Failing Test

**Files:**
- Modify: `tests/scaffolding/package.test.ts`

- [ ] **Step 1: Add the package version to the metadata contract**

Extend the parsed type with `version?: string` and add this assertion to the first package scaffolding test:

```typescript
expect(packageJson.version).toBe('0.0.1');
```

- [ ] **Step 2: Run the focused test and verify RED**

Run:

```bash
npm test -- tests/scaffolding/package.test.ts
```

Expected: FAIL because the current version is `0.1.0`, not `0.0.1`.
